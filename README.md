# Digital Twins

An iOS thesis MVP for scanning a single indoor room, reviewing a simplified 3D model and its dimensions, saving it locally, and exporting it. Built with SwiftUI and Apple RoomPlan. All scans stay on the device until the user shares them.

## Run

1. Open `DigitalTwins.xcodeproj` in Xcode.
2. Select the DigitalTwins target, then Signing & Capabilities. Choose your **personal** Apple team and change the bundle identifier if required. No team is committed in this project.
3. Connect a LiDAR-equipped iPhone running iOS 17 or later, select it as the run destination, and run the app.
4. Grant camera access. Tap Scan a room, move slowly around its perimeter, and tap Finish scan.
5. Rotate and zoom the model, inspect dimensions, enter a name, and save it. Export shares the model and both JSON files through the iOS share sheet.

The simulator cannot capture rooms. Unsupported devices display an explanation and disable scanning. They can still review existing saved rooms. Real-device validation is required before considering the capture workflow verified.

## Architecture and scope

- **Library:** lists saved rooms and handles device support and camera permission.
- **Scanner:** wraps RoomCaptureView with native coaching, observes capture errors and app interruptions, and receives the processed CapturedRoom.
- **Review:** exports a parametric USDZ preview, presents it through SceneKit with camera controls, and lists dimensions of recognized surfaces and furniture in metres.
- **Storage:** a Foundation-only Swift package with Codable metadata and staged directory commits. A model export or write failure leaves no partial library entry. Room names are never filesystem paths.
- **Export:** validates the saved files, then shares them with UIActivityViewController. Share errors are surfaced to the user.

A saved room has a UUID, name, creation date, and an array of element IDs, categories, widths, heights, and depths. Under Application Support/Rooms/<UUID>/ it contains:

| File | Contents |
| --- | --- |
| model.usdz | Parametric 3D model generated by RoomPlan |
| room.json | Complete JSON-encoded CapturedRoom, including geometry and transforms |
| metadata.json | App room record with name and dimension summary |

This is a static digital representation. Cloud accounts, live IoT data, multi-room capture, model editing, and building system integrations are outside this MVP. Measurements and recognized furniture are estimates from RoomPlan; they are not survey-grade results.

## Implementation sequence

1. Add the native scanning flow and permission/support checks.
2. Process room results and export a parametric model.
3. Add model review and element dimensions.
4. Persist complete room records locally and reopen them.
5. Share USDZ and JSON files, handle failures, and validate storage and compilation.

## Developer checks

```sh
swift test
xcodebuild -project DigitalTwins.xcodeproj -scheme DigitalTwins \
  -destination 'generic/platform=iOS' -derivedDataPath /tmp/digital-twins-build \
  CODE_SIGNING_ALLOWED=NO build
```

`project.yml` is the XcodeGen source. After project changes, run `xcodegen generate`. There are no external package dependencies.

Storage tests exercise save/reopen/export, missing export files, failed-save cleanup, invalid names, and path traversal prevention. These tests use synthetic file bytes, not RoomPlan scans, and do not establish USDZ or scanning quality.

## Physical device acceptance checklist

- Deny camera access, then enable it from Settings and retry.
- Scan a furnished room containing doors and windows. Check native coaching and the final model.
- Compare captured dimensions with manual measurements and record recognition omissions.
- Finish an empty/incomplete scan and verify error recovery.
- Interrupt scanning by locking the phone, switching apps, or taking a call. Start a fresh scan after returning.
- Save, quit the app, reopen, and confirm the model and dimensions remain available.
- Share USDZ and JSON to Files; open the USDZ in another viewer and inspect the JSON.
- Cancel sharing and retry. Test tracking/thermal failures and storage pressure where feasible.

An unsigned build does not prove any of the physical-device checks above. Device deployment requires selecting your personal Apple signing team locally.
